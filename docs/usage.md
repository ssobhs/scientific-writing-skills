# 使用说明

先确定要完成的工作：起草新正文、审查科学表达，还是修改已有文字。提供与任务相关的原稿、文献笔记、图表、数据或计算输入，并说明哪些内容已经完成、哪些仍是计划。论文页数、目标字数、引用样式和输出文件名等要求也应直接给出。

前三个 skill 按章节功能选择。需要从 PDF、图片或 DOCX 核对科学符号，或交付 Word 文件时，配合 `word-native-math`。各 skill 的参考文件是判断依据，不必把内部检查清单全部输出到论文正文。

## 安装与更新

可在 Codex 中使用 `$skill-installer`，指定仓库 `ssobhs/scientific-writing-skills` 和所需的 `skills/<name>` 路径。也可以将完整 skill 目录复制到项目的 `.agents/skills/` 或用户的 `~/.agents/skills/`。同名技能不会自动合并，应避免重复安装；安装或更新未显示时再重启 Codex。依据见 [OpenAI 官方 Build skills 文档](https://learn.chatgpt.com/docs/build-skills)（2026-10-08 查阅）。

辅助脚本按需使用，不是每次写作都要运行。建议使用 Python 3.10 或更高版本，依赖见 [requirements.txt](../requirements.txt)；目前没有跨 Python 版本测试结论。一般 LaTeX 公式转换另需 Pandoc。复制 skill 文件夹不会同时安装 Python 依赖、Pandoc 或 Microsoft Word。

## 四个提示词示例

以下示例可复制使用。将文件名替换为实际可访问的路径，并提供所述材料；示例中的文件名不是仓库附带样例。

### 1. 根据材料起草背景与绪论

```text
请使用 $cn-physics-introduction，根据我提供的“文献笔记.md”和“研究范围.md”，
起草一节中文论文背景，正文约 1500 字，不含标题和文后说明。

先理解各文献解决了什么问题、在什么条件下成立，以及仍待解决的问题。
围绕共同问题组织材料，不要逐篇排列摘要。保留文献编号与对应命题，
区分已有工作、我的已完成工作和拟开展工作，不添加材料中没有的创新点。

只使用提供的材料。局部证据不足时先完成有依据的部分，
把影响成文的缺项单列，不将写作备注混入正文。
交付可用正文和少量必要的待核对项。
```

入口：[cn-physics-introduction/SKILL.md](../skills/cn-physics-introduction/SKILL.md)。这个 skill 主要处理语言和综述组织，学习来源中的科学结果不能直接充当当前研究的依据。

### 2. 审查理论与计算方法

```text
请使用 $cn-physics-computational-methods，审查“方法原稿.md”。
“方法来源.pdf”和“计算输入.txt”是本次依据，只读取我标明的相关页和设置段落。

重点检查：方法对象和假设是否明确；公式与文字是否对应；
必要符号是否定义；计算步骤依赖和适用范围是否说清；
具体参数是否确实来自本研究对应步骤的输入。

保留正确的标准理论表述和必要术语重复，不为了句式多样而改写。
先列影响理解或准确性的实质问题及来源位置，再给必要的局部修订。
不要把软件具备的能力写成本研究已经实施的工作；
无法从输入确认的设置单列待确认，不按常见做法补齐。
```

入口：[cn-physics-computational-methods/SKILL.md](../skills/cn-physics-computational-methods/SKILL.md)。原理介绍、近似选择、数值算法和实际计算设置是不同层次；文字审查不能证明计算已收敛或结果已验证。

### 3. 根据图表撰写结果与讨论

```text
请使用 $cn-physics-results-analysis，读取我提供的原图、数据表、图注和结果笔记，
起草一节结果与讨论。正文要求 1800 至 2200 字，不含标题和说明。

先确认各图及子图对应的对象、条件、物理量定义和能量参考。
围绕“哪些差异可以由现有证据解释”组织比较，不按图号逐项报数。
保留例外、负结果和竞争解释；不要把相关性写成唯一因果，
不要添加材料中没有的显著性、误差条或收敛验证。

每个结论回查对应证据，新计算的差值和比例独立复算。
这是一个完整的多图小节，请在初稿后安排一次新上下文材料核对，
由主执行者核实必要修改，并实测最终正文字数。
图像打不开、数据有冲突或核对无法执行时，明确指出受影响部分，
不要把初稿称为已经核验的定稿。
```

入口：[cn-physics-results-analysis/SKILL.md](../skills/cn-physics-results-analysis/SKILL.md)。完整多图或多对象小节需要新上下文核对；简单片段采用有针对性的回源自检。运行环境若不能执行独立核对，应如实说明该步骤未完成。

### 4. 核对来源符号并修订 Word

```text
请使用 $word-native-math，核对“来源论文.pdf”第 3、5 个物理页和“符号截图.png”，
然后修订“原稿.docx”中我标出的科学符号和公式，另存为“修订稿.docx”。
保留原始 DOCX，只修改指定范围。

先读取来源，记录原字符、文件和页码/位置；再查看关键原页或图像区域，
判断底项、完整上下标范围，以及变量、单位、元素、索引等角色。
对有歧义或字形有科学含义的符号，保留简短的“来源观察—判断—写入方式”记录。
PDF 文字层提取不能当作 OCR 或最终识别结果；看不清时不要猜。

确认含义后再写入：普通角标使用真正的 Word 上下标属性，
复杂公式使用可编辑 OMML；字体、粗斜体和字号遵循原稿及指定模板。
不要用 Unicode 小字符或单纯缩字号代替原生格式，不要清空段落重建。

交付前回源核对符号，检查原生结构及未授权内容的保全，
在实际 Microsoft Word 中打开、另存、重开，并查看受影响页面。
报告实际完成的检查和未完成项；跳过或拒绝处理的对象不能算修复成功。
```

入口：[word-native-math/SKILL.md](../skills/word-native-math/SKILL.md)。如果这项工作同时包含正文起草或科学解释，应再加载对应的章节 skill。

## Word 工具的执行顺序

1. **读取。** 保留来源字符和定位；PDF 文字层中的编码、字符顺序和字体信息都可能需要回查。无文字层不表示页面没有内容。
2. **判断。** 对照原页、图注和定义确认符号关系。小字号只能提供线索，不能直接判断是下标、编号还是普通文字。
3. **记录。** 对易丢失结构或仍有歧义的符号，分开记录来源观察与解释。确定的符号在同一文稿中一致复用，含义改变时重新核对。
4. **原生写入。** 按已确认范围使用 Word run 属性或 OMML。既有文档局部修改并另存，不覆盖原稿。完整操作和参数见 [角标与 OMML 接口](../skills/word-native-math/references/usage.md)、[字符格式 API](../skills/word-native-math/references/rich-text-api.md)。
5. **核验。** 回源检查科学含义，检查 DOCX 结构与保全情况，再完成实际 Word 回存及受影响页面的视觉检查。结构检查、Word 回存和页面目视检查分别报告，不能相互代替。

`source_evidence.py` 对 PDF 采集文字层及字符属性，对图片检查容器、尺寸等信息；它不联网、不上传材料、不调用 OCR，也不自动识别科学符号。接口见 [PDF/图片证据工具](../skills/word-native-math/references/source-evidence-api.md)。需要 OCR 时，应另用可用工具辅助并回查原图。

现有字符格式 API 不自动识别全文语义，也不代替 Word 操作；字段、修订、内容控件、图形或图片中的文字，以及超出接口范围的对象，需要另行处理。Pandoc 转换成功也不能证明任意 LaTeX 宏已正确恢复。未完成的检查应保留为待办，不声称已经通过；本项目不据此宣称 WPS 或 LibreOffice 的兼容性已经验证。

## 如何判断一次交付是否完成

对写作任务，先看最终正文能否回答任务要求，再核对科学含义、条件、引用、完成状态及实际篇幅。正确自然的原文可以保留，不需要为了显示修改量而继续改写。

对 Word 任务，除正文外还要确认修改范围、原生格式和实际显示效果。脚本报告只是其中一层证据。无法读取材料、存在影响结论的歧义或缺少实际 Word 核验环境时，应指出具体阻塞和影响范围，等待解决相应问题。
