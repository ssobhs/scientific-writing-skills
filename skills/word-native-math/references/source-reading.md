# 从来源恢复符号和格式

## 按文件类型取证

**DOCX**：保留run、字符样式、段落样式与默认设置，读取原生vertAlign和OMML结构。粗体/斜体属性为None时不能据此判定“不粗/不斜”；读取继承或用Word有效格式确认。表格、页眉页脚、脚注、图注、文本框和公式可能不在普通段落遍历范围内；仅在与本次任务相关时扩展检查，并说明未覆盖范围。不要先转成纯文本再判断格式。

**有文本层PDF**：提取文本用于检索和初步阅读，字符坐标、字体名、字号和原页图用于核对。PDF常没有Word那样的“下标”标签，只是把字符画在不同位置。小字号、基线偏移、相邻底项和上下文共同形成证据；单个字号阈值不构成语义判断。字体名可能是子集或自定义名，伪粗体/斜切亦可能没有明显字体名。pdfplumber的upright主要反映字符是否旋转，**不是正体/斜体语义判断**。

**扫描PDF、截图、照片**：实际查看整页或能定位的区域，再对关键符号裁剪放大；记录页码/区域与原图尺寸。OCR可辅助定位，仍要核对上/下位置、完整范围和上下文；没有OCR输出就不能写“已OCR识别”。放大低清像素不增加原始信息；不要通过AI补图后把生成笔画当科学依据。

**TXT、复制文字、Markdown、网页摘要**：纯文本通常不携带完整字形语义。Unicode角标和显式LaTeX只能提供部分线索；对敏感记号回到原始资料。若只有纯文本，可靠定义可支持带依据的规范化，不能称其为“原图观察”。无法确定且影响物种/指数/电荷/变量意义时提出具体待确认问题。

## 常见混淆及处理

|表现|需要核对的关系|不能采取的捷径|
|---|---|---|
|D3h、D₃h、C78|点群完整下标3h与元素计数78；(5)异构体编号保持基线|只把可见的小数字下标化，遗漏h|
|x_i、E_F、G^r|变量索引i、说明标记F、retarded标签r分别有什么定义|把所有下标或上标都套同一正斜体|
|粗斜体k、普通斜体k|前者是否矢量，后者是否分量/模；原文有没有定义|只保留字符串k，丢掉维度角色|
|m、m²、kg m⁻³|质量变量m与米单位m；指数及负号完整|“字母是变量所以全部斜体”|
|小字号图注、脚注号、文献号、式号|字号是版面层级还是与底项组成一个符号|小于正文10pt就自动判下标|
|O/0、l/1/I、ν/v、μ/u、−/连字符、prime/撇号|字形、学科定义及同符号其他清晰位置|按最常见词或已知化学式自动改写|
|多行/双栏公式、上下限分散到别行|原式二维关系、左右栏、括号和上下限归属|把抽取行直接串接成一个公式|
|图片中粗斜体、文字层正常|图中文字不一定进入PDF文字层，需看图|只提取正文就声称读过整幅图|

“规范化”与“更正原稿”分开。来源确实有排版错误但定义明确时，记录原样与修正依据再输出；来源互相矛盾时不静默择一。Unicode数学字母有时表达向量、集合等不同语义，全局NFKC会抹平差别；仅对已确认的局部符号转换为普通字符加原生格式。

将“原样转写”与“按论文约定规范化”明确区分：原样转写保留已确认的粗斜体；规范化若改变原字形，分别记录原字形、目标字形及理由。不要因为M用来代称金属就自行把原页正体M改成斜体；小字号负例也可能含局部粗体，确认不是下标不等于可以抹掉其他格式。积分的微分符号d与变量x等即使紧邻，也须分别检查正斜体。为关键对象给出spans/LaTeX前，再将每段目标属性与观察逐项对照一次。

## 最小识别记录

只为关键符号保存必要记录，例如：

```json
{
  "source": {"file": "paper.pdf", "pdf_page_1based": 3, "printed_page": "012345-3", "region": "正文左栏首段"},
  "raw_text": "LaU@D3h(5)-C78",
  "observed": "原页显示3h在D右下方，78在C右下方，(5)与正文基线相同",
  "semantic_notation": "LaU@D_{3h}(5)-C_{78}",
  "roles": {"3h": "点群下标", "(5)": "异构体编号", "78": "元素计数"},
  "status": "verified",
  "basis": "原页目视与同段定义一致"
}
```

上例是格式示范，不是实际阅读证据。只有真的查看原页才填observed。用pending标记仍有歧义，列出候选、原因和所需的更清晰来源；不要填虚假的置信分数。用normalized_from_definition标明仅从可靠定义规范化、未观察到原字体的情况。

随后从该记录构造Word片段，保留对应关系。复杂公式另存LaTeX/结构表达与来源定位。核验时用来源与记录检查Word，不能只把生成结果同自己的输入比较就宣布识别正确。

识别记录不是任意脚本都能直接消费的代码。交给生成工具前核对实际接口；例如原生左角标API使用base/sub/sup，不用未经转换的subscript/superscript键。该转换只改接口字段，不改科学内容；有歧义的记录不得与已确认记录一起自动生成定稿。

## 工具边界

[source_evidence.py](../scripts/source_evidence.py)只导出PDF字形信息或图片元数据，辅助定位，不执行科学语义识别、自动OCR或自动上下标判定。方法与参数见[证据工具接口](source-evidence-api.md)。工具返回文本不等于已经读图；文字层为空也不表示页面没有内容。
